面试官问题与追问整理
1. 项目整体架构
主问题：你这个项目整体架构能介绍一下吗？
追问：
- 你们这个是跨境电商 SaaS 是吧？
- 你们平台不负责商品查看、下单那些，是吧？
- 也就是说下单是在第三方电商平台完成，你们只做后续管理？


2. QPS 3000 是什么接口
主问题：你写的 QPS 峰值 3000 多，这个 QPS 是哪个接口的？
追问：
- 是单个接口，还是整体接口？
- 创建订单之后冻结库存，是你们这边创建订单吗？
- 你刚刚说的峰值 QPS 主要是哪个接口？刚刚没听清楚。
- 你们现在是直接用 MySQL 去扛 QPS 3000 吗？
- 高峰期压测过吗？已经上线了吗？能扛住吗？
- 一天订单量六七万，为什么峰值 QPS 能到 3000？


3. 第三方订单如何进入你们系统
主问题：第三方平台下了订单，你们这边是怎么感知的？
追问：
- 这个交互流程是怎么样的？
- 是 WebHook 还是定时任务拉取？
- 定时拉取后，是批量扣减库存吗？
- 拉到订单之后，你们后续有哪些业务？


4. 库存同步与一致性
主问题：你们这边库存最主要的作用是什么？
追问：
- 电商平台有没有可能和你们库存不一致？
- 第三方平台怎么知道商品有多少库存？
- 库存数量一般是不是会展示给用户？
- 是你们主动推给第三方平台，还是平台来查你们？
- 主动推送会不会导致两边库存数量不一致？
- 秒杀、高峰期抢购场景下不会出现问题吗？
- 这样说，电商平台是不是还是要自己维护一份库存？
- 你刚刚不是说不推荐他们自己设置库存吗？
- 你们推荐的方式是什么？
- 怎么解决超卖或者少卖？

5. 库存扣减防超卖
主问题：数据库扣减库存时，有没有遇到扣成负数？
追问：
- 你这里是冻结库存，是吧？
- 库存不够、扣减后变负数怎么办？
- 有没有超卖或者少卖？
- 多个平台订单并发下，库存准确率 100% 是怎么保证的？
追问意图：考察并发扣减库存的核心方案。重点应该回答：数据库原子更新、where available_stock >= quantity、事务控制、失败回滚/补偿、幂等、防重复扣减。

6. Redis 预扣减方案
主问题：如果 QPS 后面变成 3 万，还有没有其他方案做库存冻结？
追问：
- Redis 预扣减之后呢？
- 大概流程介绍一下。
- 没考虑过是吧？
追问意图：他在考你高并发库存方案升级。期望你能讲：Redis 预扣减、Lua 原子脚本、MQ 异步落库、库存流水、失败补偿、最终一致性。

7. 多租户是什么
主问题：你刚刚说的多租户，能介绍一下吗？
追问：
- 什么是多租户？
- 每张表都有租户 ID，是这样吗？
- 除了租户 ID 这种方式，还了解过其他租户数据隔离方式吗？
- 每个租户分库/分表，除此之外还有吗？
追问意图：考 SaaS 多租户模型。包括共享库共享表、共享库独立表、独立库，以及数据隔离、安全性、成本、扩展性。

8. 大租户数据倾斜
主问题：如果某个租户数据量特别大，遇到过吗？
追问：
- 比如网红店，占 10%、20% 订单量怎么办？
- 只是数据库单独分给他，是吧？
- 请求进来怎么路由？
- 怎么知道路由到这个租户对应的库或表？
- 路由规则是怎样的？
- 是不是按租户 ID 写死定制化？
追问意图：考分库分表和路由策略，尤其是大租户隔离、热点租户处理、ShardingSphere 路由规则。

9. 按月分表后的查询问题
主问题：你们现在分了几张表/几个库？
追问：
- 按月份分表是吧？
- 如果查几个月、半年数据，怎么处理？
- 是代码查多张表再汇总吗？
- 每个月新增表，难道要改代码吗？
- 查询近半年，每次涉及的表不一样，怎么处理？
- 页面查询不是导出，想效率更快怎么办？
- 难道要在代码里做分页逻辑吗？
- 汇总表会不会很大？
- SaaS 场景下，租户一般只看自己的数据，按月份分表效率是不是会低？
追问意图：他觉得你按月分表的方案对“租户视角查询”不一定最优，所以追问查询性能、跨表分页、动态路由、索引设计、冷热数据、汇总表等问题。

10. 分库和分表的区别
主问题：分库和分表分别是为了解决什么问题？
追问意图：基础概念题。分表主要解决单表数据量大、索引膨胀、查询慢；分库主要解决单库连接数、IO、CPU、存储压力和并发瓶颈。
